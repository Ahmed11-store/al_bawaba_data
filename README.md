# البوابة - Al-Bawaba

تطبيق أوفلاين 100% (Flutter/Dart) للفحص الصوتي للوحات السيارات ومطابقتها بقاعدة بيانات محلية.

## المتطلبات قبل التشغيل

- Flutter SDK 3.3+ مثبت (`flutter doctor` بيرجع علامات صح).
- جهاز Android حقيقي متوصّل بسلك USB (الميكروفون وخاصية on-device speech recognition غالبًا مش بتشتغل صح على المحاكي/emulator).
- **حزمة اللغة العربية للتعرف الصوتي الأوفلاين مثبتة على الجهاز**:
  الإعدادات ← Google ← Voice ← On-device recognition ← نزّل العربية.
  من غيرها، `SpeechRecognitionService.initialize()` هيرجع `false` والتطبيق مش هيقدر يسمع.

## خطوات التشغيل

```bash
# 1. من داخل مجلد المشروع
flutter pub get

# 2. تأكد إن الجهاز متوصّل
flutter devices

# 3. شغّل
flutter run
```

## إضافات لازم تعملها بنفسك قبل الإصدار النهائي (Production)

هذول مش أخطاء في الكود، لكنهم قرارات محتاجة مدخلات منك مش أقدر أعملها في بيئة sandbox من غير إنترنت:

1. **خط Tajawal/Cairo**: التطبيق حاليًا شغال بخط النظام الافتراضي (Noto Sans Arabic على أغلب أجهزة Android، بيدعم العربي كويس). لو عايز فعليًا Tajawal زي ما في تصميم السبك:
   - نزّل من https://fonts.google.com/specimen/Tajawal (رخصة OFL مجانية)
   - حط ملفات `.ttf` في `assets/fonts/`
   - فعّل الـ `fonts:` block في `pubspec.yaml` (موجود commented-out وجاهز)

2. **صوت التنبيه**: مبني ملف WAV حقيقي (نغمتين متبادلين، إنذار كلاسيكي) في `assets/audio/wanted_alert.wav` — شغال فورًا، بس لو عايز صوت buzzer/siren احترافي بدّله بنفس الاسم والمسار.

3. **الـ 50,000 لوحة الحقيقية**: التطبيق بيعمل seed تلقائي بـ 3 سجلات تجريبية بس (`assets/data/sample_blacklist.json`) عشان تقدر تجرب المطابقة فورًا. زرار الاستيراد الحقيقي موجود وشغال في تبويب "الكل" (`ImportExportService.pickAndParseBlacklistFile`) — كان فيه باج في التطبيع بيمنع اللوحات المستوردة من المطابقة أبدًا، اتصلح (تفاصيله تحت في "إصلاح مهم").

## نظام الاشتراك الشهري (تفعيل أوفلاين)

الدفع بيتم بره التطبيق تمامًا (فودافون كاش / إنستاباي / تحويل بنكي — زي ما تحب)، والتفعيل نفسه أوفلاين بالكامل، من غير أي نت في أي خطوة. خطوات الاستخدام:

1. أول ما العميل يفتح التطبيق، هيشوف شاشة "تفعيل" فيها **كود جهاز** فريد (8 حروف/أرقام) — العميل يبعتهولك مع إثبات الدفع.
2. انت تشغّل على جهازك (مرة واحدة `flutter pub get` كافية للأداة برضو، مش محتاج حاجة زيادة):
   ```bash
   dart run tool/generate_license.dart <كود جهاز العميل> <عدد الأيام>
   # مثال لاشتراك شهري:
   dart run tool/generate_license.dart 3F2A9B10 30
   ```
3. تبعت للعميل الكود اللي طلع (شكله `XXXX-XXXX-XXXX-XXXX`)، وهو يكتبه في شاشة "تفعيل" — التطبيق يشتغل بعدها أوفلاين بالكامل لحد نهاية المدة، من غير أي نت خالص.
4. لما الاشتراك يخلص، التطبيق يرجع لشاشة "تفعيل" تلقائيًا ويطلب كود جديد (تكرر نفس الخطوات).

**قبل أول بيع فعلي:** لازم تغيّر القيمة الافتراضية في `lib/core/license_secret.dart` (`kLicenseSecret`) لقيمة عشوائية خاصة بيك، ومتحطهاش في أي repo عام. الملف نفسه فيه شرح تفصيلي لحدود النظام الأوفلاين ده (مفيش سيرفر = مفيش حماية 100%، بس بيمنع نسخ الكود بين الأجهزة والتلاعب بساعة الموبايل).

## التحديث التلقائي (للتطبيق نفسه ولقاعدة اللوحات)

فيه نوعين مختلفين من "التحديث"، ولازم تفهم الفرق:

**١. تحديث التطبيق نفسه (كود جديد/APK جديد):** محتاج تفاعل بسيط من العميل — أندرويد بيمنع أي تطبيق عادي (مش من Google Play) إنه يثبّت نسخة جديدة من نفسه بصمت، ده قيد نظام تشغيل مش حاجة في إيدي. اللي بيحصل: التطبيق يتفقد تلقائي لو فيه إصدار جديد على GitHub، يوريله رسالة، والعميل يدوس زرار واحد بس ("تحميل التحديث") — بعدها أندرويد يطلب تأكيد "تثبيت؟" مرة واحدة وخلاص.

**٢. تحديث قاعدة اللوحات (بيانات اللوحات المطلوبة):** ده تلقائي بالكامل 100%، من غير أي تفاعل من العميل خالص — لأنه مجرد تحميل ملف بيانات وتحديث قاعدة البيانات المحلية، مش تثبيت تطبيق، فمفيش قيد من أندرويد عليه.

### الإعداد (مرة واحدة بس)

الاتنين بيستخدموا نفس الـ GitHub repo:

1. اعمل حساب GitHub لو مفيش (مجاني).
2. اعمل repo عام (public) — مش لازم يكون فيه كود مشروعك، ممكن يكون فاضي غير ملفات التحديث.
3. افتح `lib/services/update_service.dart` وغيّر:
   ```dart
   const String kUpdateRepoOwner = 'your-github-username';
   const String kUpdateRepoName = 'al-bawaba-releases';
   ```
   لاسم المستخدم واسم الـ repo بتوعك.
4. ضيف إذن الإنترنت في `android/app/src/main/AndroidManifest.xml` (الاستثناء الوحيد من "أوفلاين بالكامل" — بس لتفقد التحديثات، مش للتشغيل اليومي):
   ```xml
   <uses-permission android:name="android.permission.INTERNET" />
   ```

### تحديث التطبيق (كود جديد)
اعمل "Release" جديد على GitHub بتاج زي `v1.1.0`، وارفعله ملف الـ APK كـ asset. خلاص.

### تحديث قاعدة اللوحات (بيانات)
ارفع/عدّل ملف اسمه `blacklist_sync.json` في جذر نفس الـ repo (فيه نموذج جاهز في `blacklist_sync.example.json` بالمشروع ده — انسخه وسمّيه `blacklist_sync.json`). كل مرة عايز تحدث القائمة:
1. عدّل مصفوفة `records` (نفس أسماء الأعمدة اللي الاستيراد اليدوي بيقبلها).
2. **زوّد رقم `version` بـ 1 على الأقل** — ده اللي بيخلي كل نسخ التطبيق تعرف إن فيه جديد. لو نسيت تزوده، محدش هياخد التحديث.
3. اعمل commit/push.

كل نسخة تطبيق عند العملاء هتاخد التحديث تلقائيًا أول ما تتفتح وعندها نت — من غير ما حد يعمل حاجة، وهيظهر إشعار بسيط تحت يأكد إن العدد اتحدث. فيه كمان زرار "تحديث الآن" يدوي في شاشة "اللوحات المطلوبة المستوردة" لو عايز تتأكد فورًا من غير ما تستنى فتح التطبيق تاني.

**ملاحظة:** الملف اللي على GitHub بيُعتبر القائمة الكاملة النهائية، مش إضافة — كل تحديث بيستبدل كل قاعدة اللوحات المحلية بالكامل، مش بيضيف عليها.

## إصلاح مهم: مطابقة اللوحات المستوردة

قبل كده، اللوحات المستوردة من ملف CSV/JSON كانت بتتخزن زي ما هي من غير تطبيع (Arabic-Indic digits، اختلافات صيغ الحروف...)، بينما اللوحات اللي بتتسمع صوتيًا بتتطبّع قبل المطابقة — يعني أي اختلاف بسيط في صيغة الملف المستورد كان بيخلي المطابقة تفشل بصمت، رغم إن الاستيراد "بينجح" ظاهريًا (العداد بيزيد). اتصلح في `PlateRecord.fromSeedRow` — كل استيراد جديد دلوقتي بيتطبّع بنفس منطق التعرف الصوتي بالظبط. كمان اتضافت شاشة لعرض اللوحات المستوردة نفسها (كانت مش موجودة أصلاً، بس عداد رقمي) — دوس على كارت العداد في تبويب "الكل".

```
lib/
  core/
    arabic_plate_normalizer.dart   # تطبيع النص العربي وفصل حروف/أرقام اللوحة
    app_theme.dart                 # الألوان والثيم الداكن
    base32_codec.dart              # ترميز/فك أكواد التفعيل (بدون مكتبات خارجية)
    license_secret.dart            # السر المشترك لتوقيع أكواد التفعيل — غيّره قبل الإصدار
  models/
    plate_record.dart              # سجل اللوحة المطلوبة (blacklist) — بيطبّع عند الاستيراد
    scan_log.dart                  # سجل كل عملية فحص
  services/
    speech_recognition_service.dart  # التعرف الصوتي أوفلاين
    audio_alert_service.dart         # صوت + اهتزاز + إيقاف/استئناف الاستماع
    database_service.dart            # SQLite (جدولين: blacklist, scan_logs)
    location_service.dart            # GPS
    import_export_service.dart       # استيراد CSV/JSON + تصدير CSV
    license_service.dart             # التفعيل الشهري الأوفلاين
  providers/
    inspection_provider.dart       # الحالة المركزية (يربط كل الخدمات ببعض)
  screens/
    app_gate.dart                  # يقرر: شاشة التفعيل ولا التطبيق الأساسي
    activation_screen.dart         # شاشة تفعيل الاشتراك
    inspection_screen.dart         # تبويب "الفحص"
    wanted_matches_screen.dart     # تبويب "مطلوبة"
    all_logs_screen.dart           # تبويب "الكل"
    blacklist_screen.dart          # عرض/بحث اللوحات المستوردة
    main_navigation.dart           # الـ Bottom Navigation
  widgets/
    audio_level_meter.dart
    wanted_alert_modal.dart
    plate_data_table.dart
  main.dart
tool/
  generate_license.dart            # أداة توليد أكواد التفعيل — تشتغل على جهازك انت، مش جوه التطبيق
```

## ملاحظة صريحة

الكود اتكتب واتراجع سطر بسطر للتأكد من تطابق كل الأسماء والمسارات بين الملفات (مفيش أي دالة أو حقل بيتنادى باسم غلط)، لكن معنديش Flutter SDK في بيئة الترميز دي عشان أعمل build فعلي وأتأكد إنه بيتصرف بالظبط زي المتوقع على جهاز حقيقي. أول build عندك ممكن يطلع تحذيرات بسيطة من الـ linter (زي unused import لو عدّلت حاجة) — دي حاجات عادية مش أخطاء تكسر التطبيق.
